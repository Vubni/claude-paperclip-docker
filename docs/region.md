# Регион и сетевой доступ

Без профиля лаунчеры используют текущую сеть Mac и Docker, английский язык Linux и прежние тома. Проверка требует ровно один присвоенный двубуквенный код страны. RU, неизвестные коды, повторное поле страны и сетевые ошибки блокируют запуск. Внешние ссылки из Paperclip в известных российских доменных зонах блокируются. В обычном режиме у работающих приложений сохраняется прямой доступ в интернет.

### Выбор строгого режима

1. Для строгого режима требуется Docker Engine с поддержкой изолированного режима bridge и Compose 2.24.4 или новее. Подготовьте VPN на хосте с выходом в нужной стране и выделенный **HTTPS CONNECT-прокси** с постоянным публичным IPv4 выхода в той же стране. Нужны имя из действующего публичного TLS-сертификата, фиксированный IPv4 и порт прокси. Шлюз поддерживает прокси с авторизацией по исходному адресу и туннелирование до числового IPv4 назначения на порт 443. Подключение по логину и паролю и автоматическая покупка или настройка VPN в эту версию не входят.
2. Остановите в Docker Desktop контейнеры этих трёх рабочих пространств, включая старые региональные шлюзы, перед сменой режима или профиля. Данные сохраняются в существующих томах. После смены настроек уже запущенный обычный контейнер продолжил бы использовать прежнюю сеть, поэтому редактор применяет смену профиля только после остановки рабочих пространств, а лаунчер дополнительно проверяет совместимость всех трёх проектов до запуска.
3. На macOS откройте **Настройки региона…** в меню любого из трёх приложений или запустите `Настройки региона.command`. Выберите страну и один из её часовых поясов. Введите параметры прокси, ожидаемый адрес выхода и разрешённые домены внешних сервисов. Сохраните настройки и запустите нужные приложения. При смене страны или адреса профиль обновляется вручную. Наблюдаемый адрес никогда не записывается автоматически как новый доверенный.
4. На Linux и WSL 2 файл читается из `$XDG_CONFIG_HOME/claude-paperclip-workspace/region.json` (обычно `~/.config/claude-paperclip-workspace/region.json`). Завершите три Compose-проекта и их шлюзы, создайте родительскую папку с правами 700 и сохраните заполненный шаблон с правами 600. Для возврата в обычный режим после остановки переименуйте файл. На macOS общий файл находится в `~/Library/Application Support/Claude Paperclip Workspace/region.json`. Его можно открыть через меню настроек. При ручном редактировании используйте атомарную замену файла после остановки рабочих пространств. При работе через WSL проверка страны выполняется в Windows, в дистрибутиве WSL и в Docker. Для возврата к обычной сети остановите приложения и шлюзы в Docker Desktop и выберите **Вернуть обычный режим**. [Шаблон профиля](../region/region.example.json)

Выбранный часовой пояс применяется к Linux-клиенту, серверу, отдельному Firefox и ручному shell. Английские языковые предпочтения Linux и переключатель языка Paperclip сохраняются. Локальный просмотр WebKit использует настройки macOS. Учетная запись, платёжный регион и системные настройки Mac этим профилем не меняются.

### Что ограничивает строгий профиль

- Каждый Compose-проект получает внутреннюю изолированную сеть. У приложения нет прямого маршрута в интернет и внешнего DNS. Шлюз обслуживает локальный просмотр через порт на loopback и пересылает разрешённые HTTPS-соединения через TLS к указанному IPv4 прокси с проверкой сертификата. Для внешней сети приложения доступны только CONNECT на порт 443 и IPv4. Прикладные клиенты без поддержки прокси теряют внешний доступ.
- На хосте проверяется выбранная страна, а через прокси проверяются страна и точное совпадение IPv4 выхода по Cloudflare. Внутри workload перед обычным запуском выполняется дополнительная проверка через тот же путь. Шлюз также сверяет оба адреса прокси с локальной базой стран. Только служебные запросы к Cloudflare и загрузка базы DB-IP разрешены до открытия пользовательского трафика. Для штатной проверки к списку доменов добавлен `www.cloudflare.com`.
- Для разрешённого домена шлюз получает IPv4 через DNS over HTTPS по тому же прокси, проверяет адрес по месячной базе стран и передаёт именно проверенный адрес в CONNECT. Адреса RU, неопределённые и непубличные блокируются. `*.example.com` разрешает поддомены, корневое имя добавляется отдельно. Для провайдеров входа и API понадобятся их фактические домены. Новая месячная база загружается через прокси, а доступ открывается после повторной проверки выхода. [DB-IP Country Lite, CC BY 4.0](https://db-ip.com/db/download/ip-to-country-lite)
- Шлюз и отдельный процесс на хосте повторяют проверки с паузой 5 секунд. Для передачи данных нужны два короткоживущих разрешения. Срок составляет до 18 секунд для выхода прокси и до 20 секунд для Mac. При ошибке или истечении срока шлюз закрывает активные соединения, включая просмотр. Запасной прямой маршрут отсутствует. Это интервальная проверка геолокации. Выделенный прокси должен действительно использовать один выход для всех назначений. Геобазы не устанавливают владельца сервиса, транзит или местонахождение конечного хранилища.
- В строгом режиме Paperclip запускается с UID/GID 1000, без Linux capabilities, с запретом повышения привилегий. Для ранее созданного тома нужен доступ на запись у UID 1000. В обычном режиме штатный entrypoint сохраняет возможность подготовить старый том и сбросить права; из контейнера убраны NET_RAW и повышение привилегий. Обмен приложений ограничен прежним подкаталогом проектов.
- Установка образов обращается к реестрам и репозиториям через сеть Docker Desktop. Во время установки проверяется страна, а подготовка каталога проектов выполняется без сети. Политика строгого шлюза относится к запущенным через лаунчер рабочим пространствам. Администратор Docker по-прежнему управляет сетью хоста, образами и прямыми запусками.

### Проверка

`./Install.command --launchers-only` обновляет только приложения macOS с их прежними идентификаторами, без сборки образов и перезапуска рабочих контейнеров. Установленный `Contents/Resources/Workspace.command --region-check` выполняет обе проверки страны до запуска основного приложения. Строгий режим при этом подготавливает свой шлюз.

Из корня репозитория запустите `python3 -B -m unittest discover -s tests` с Python 3.11 или новее. Отдельный тест `python3 tests/docker_isolation.py` использует Docker Desktop, OpenSSL и локальный образ `python:3.12-slim-bookworm`. Тест создаёт временный Compose-проект без рабочих томов. Проверяются отсутствие прямого IPv4/IPv6 и внешнего DNS, недоступность порта хоста из workload, локальный просмотр, TLS CONNECT и разрыв уже открытого туннеля после отзыва разрешения. Штатный Paperclip ui-v6 также достиг `/api/health` с UID 1000 и пустым набором capabilities на новой тестовой базе без сети. Запросы через реальный curl и тестовый HTTPS-прокси отдельно проверены с закреплением адреса и отказом при недоверенном сертификате. Вход в личный аккаунт и сквозная работа с настоящим выделенным региональным прокси в проверку не входили.
